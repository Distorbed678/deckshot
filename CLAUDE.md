# Deckshot (LÖVE 11.5 / LuaJIT)

Deckshot (formerly "Rounds Clone"): a fan-made game heavily inspired by ROUNDS (credit Landfall in the README and Credits). 2D side-view duels where the round losers pick upgrade cards. Local play is 2-4 players (keyboard P1/P2, gamepads, touch, bots; FFA or Teams). Online play supports up to 4 players over Steam (AppID 480 "Spacewar") or LAN (Online Play → Steam / LAN). Repo: `Distorbed678/deckshot`.

## Running and checking
- **Linux dev machine (current):** `love` 11.5 and `luajit` are on the PATH and Steam is installed. Run with `love .` from the repo root. Check syntax with `luajit -bl file.lua > /dev/null`. Headless harnesses run with `love <harnessDir>`. Save folder: `~/.local/share/love/deckshot/`.
- **Windows PC:** LÖVE 11.5 may be at `%LOCALAPPDATA%\Programs\love-11.5-win64` (`love.exe`, plus `lovec.exe`, which prints to the console); if it isn't, download `love-11.5-win64.zip` into the scratchpad and syntax-check by `loadfile`-ing every file in a harness. Steam is **not installed** there, and neither are `zip`, `gh` or Python (Windows' `tar.exe -a -c -f x.zip` makes zips; Node and Chrome are installed). Checked-out files use CRLF (`core.autocrlf=true`). From Git Bash, `npx love.js` silently does nothing: run `node <npm-cache>/_npx/*/node_modules/love.js/index.js` instead. Put `io.stdout:setvbuf("no")` in harnesses, or redirected output is lost.
- The desktop game runs on **LuaJIT (Lua 5.1)**, so don't use `//`, `&`/`|` or other 5.4 features. Use `love.data.pack`, and get bit operations with `require "core.bit"` (never `require "bit"` directly).
- **The game also runs in the browser** (love.js, plain Lua 5.1: no JIT, no `ffi`, no `bit`, no `goto`, no luasocket). `core/platform.lua` sets `platform.web` (from `love._os == "Web"`). On the web: no Steam, LAN join only (through `online/webbridge.lua`), no custom `love.run` (love.js drives frames), `Settings.applyWindow` does nothing (the page owns the canvas), the Video tab shows only the effects options, and Quit is hidden. Anything new that touches the window, files outside the save folder, native libraries or `ffi` must be guarded with `platform.web`.
- Without Steam (or on an unsupported OS) `online/steam.lua` fails gracefully and online play is disabled.

## Building releases
`./build.sh [all|linux|windows|web|site|love]` (Linux; needs curl, zip, unzip, and Node.js for `web` and the Windows icon) writes to `dist/`:
- `Deckshot.love`: the game files (everything except `docs/`, `lib/`, `web/`, `site/`, `*.md`, `*.sh`, `steam_appid.txt` and build output). `build_love` checks it contains `data/maps/order.txt`.
- The game's icon is `assets/icon.png` (window and AppImage) and `lib/windows/icon.ico` (the `.exe`, applied with `resedit-cli` before the .love is appended). Both are drawn from `Logo.drawMark`.
- `Deckshot-x86_64.AppImage`: LÖVE's AppImage with `Deckshot.love`, the Steam `.so` files and `web/` at the AppDir root. `FUSE_PATH` is set in `AppRun`, so the game runs fused.
- `Deckshot-windows-x64.zip`: `Deckshot.exe` (love.exe with the .love appended), LÖVE's DLLs, the Steam DLLs and `web/`.
- Both desktop packages carry the browser build in `web/` (`copy_web`; the web build runs first) so a LAN host can serve it to browsers.
- `web/`: `npx love.js@11.4.1 -c` output (compatibility mode: no SharedArrayBuffer, so it works on GitHub Pages) with `web/index.html` (and `web/manifest.json`) replacing love.js's page. The page also handles phones (full-screen layout, rotate overlay, audio unlock on first tap, a hidden `<input>` for the phone keyboard; see `core/webkeyboard.lua`). The page sizes the canvas drawing buffer to its on-screen size and sends a `resize` event so LÖVE renders at native resolution. It also stops `fullscreenchange` events before SDL sees them, because otherwise SDL treats the page's fullscreen as its own and stops following the canvas size.
- **GitHub Pages:** `.github/workflows/pages.yml` runs `./build.sh site` and deploys `dist/site` (the landing page from `site/index.html` at the root, the game under `play/`, images from `docs/media/`) on every published release and on manual dispatch (`release.yml` dispatches it, because a release created with the workflow token doesn't fire the release event). Live at https://distorbed678.github.io/deckshot/. The `github-pages` environment allows deploys from `main` and from tags matching `v*` (releases run from their tag); a new tag scheme needs adding under Settings → Environments.

The LÖVE runtimes and appimagetool are downloaded once into `build/cache/` (gitignored). If you add asset folders, make sure `build_love` doesn't exclude them.

## Workflow: commit and release every change
**After every bug fix or change, commit it, push it and publish a GitHub release, unless the user says not to commit or release yet.**
1. Run the relevant checks first (syntax check, headless harnesses, screenshots).
2. Commit with a descriptive message and push to `main`. If the push can't find credentials (the global `credential.helper` is `cache`), push with `git -c credential.helper= -c credential.helper='!gh auth git-credential' push origin main`.
3. Publish by pushing an annotated version tag (works from Windows or Linux, no `gh` needed locally). `.github/workflows/release.yml` then runs `./build.sh all` on Linux, checks both packages contain the game, the Steam libraries and `web/`, creates the release with both files, and starts the Pages deploy:

       git tag -a vX.Y.Z --cleanup=verbatim -F <notes.md> && git push origin vX.Y.Z

   - The tag message is the release notes: what was fixed or changed, and whether online play is still compatible with the previous version (if `session.PROTOCOL` was bumped, say so). The workflow appends the download table and SHA-256 checksums. `--cleanup=verbatim` keeps `#` headings (git would strip them as comments).
   - On Linux you can still build and smoke-test locally first (`./build.sh all`, launch the AppImage and confirm it loads the bundled Steam libraries). If the change could affect the browser version, test a web build in headless Firefox/Chrome (see Testing).
4. Versioning: bump the patch version (v0.1.1 → v0.1.2) for fixes and small changes, and the minor version (v0.1.x → v0.2.0) for feature batches. Check the latest tag with `git ls-remote --tags origin`.
5. Check the runs: `gh run list --repo Distorbed678/deckshot --limit 2`, or without `gh`, `curl -s https://api.github.com/repos/Distorbed678/deckshot/actions/runs?per_page=3` (public repo).

## Architecture
`main.lua` and `conf.lua` stay at the repo root (LÖVE requires it). Modules are required by dotted path, e.g. `require "game.world"`, `require "online.net"`.

| Path | Role |
|---|---|
| `main.lua` / `conf.lua` | Entry points. `conf.lua` calls `steam.init()` before the window exists. `main.lua` overrides `love.run` (FPS cap), handles F11 / Alt+Enter, touch and gamepad events, the crash screen (`love.errorhandler`, writes `crash.txt`) and the window icon. |
| `core/app.lua` | Screen stack (`switch`/`push`/`pop`). 1280×720 virtual units letterboxed to the window; `app.canvas` / `app.fonts.*` are built at the window's scale (and the text size option, `app.textScale`). `app.switch` and `app.slide()` slide the new frame in from the right (`app.noSlide` turns it off, e.g. in harnesses). Always draw through `app.fonts` and `app.canvas`; never cache them across frames. `app.gamepadpressed` maps the d-pad/A/B to menu keys unless the top screen uses them. |
| `core/ui.lua` | Immediate-mode widgets (`button`, `cycler`, `textField`, `panel`), with UI sounds, hover/press animation and shared theme colours. Only the top screen's widgets get input, so overlays must be pushed screens. `ui.printFit` shrinks text to a width. `ui.beginScroll`/`endScroll` make a clipped scrolling region. `ui.readOnly` shows widgets without letting them change (`viewOnly` buttons still work). `ui.capturing` hands navigation keys to a key-binding screen. `ui.textWasActive` tells `core/webkeyboard.lua` to open the phone keyboard. |

Emits `world.on.{toast,roster,pick,kill,matchOver}`. |
| `game/player.lua` | Movement (constants in `MOVE`), dash, melee (`MELEE`), arena edges / barrier (`checkBounds`), blocking, cards' effects, triggers (`Player:trigger`), stats tracking (`p.st`). Players read `self.input`, never the keyboard. `self.game` is the World. |

The body rides `p.leg` above the ground: terrain collision and floor hazards include the legs, bullets and melee only hit the round body. The gun's look comes from stats (`weaponOf`); clients compute `p.weaponStats` from the roster. Players are solid to each other through `Player:withBodies` (clients use `predWorld.bodies`). |

| `game/objects.lua` | Map objects: hazards, breakables, ropes, spawned effects (pickups, gas clouds, lightning strikes). Instances are rebuilt from `map.objects` each round (`Objects.build`); solid ones join `world.solids`. Hazard hits go through `Objects.hazardHit` (shove, block bounce). |

| `gfx/cardart.lua` | Card art drawn in code: motifs (in a -1..1 box, using its `seg`/`arc`/`star` helpers, never `love.graphics.line`, whose smoothing breaks under scaling), the medallion, and the rarity glow and foil shader. Cards without an `art` line get one guessed from their stats. |
| `gfx/recap.lua` | The match recap: stats, builds and awards from data clients already have, saved as an image (`recaps/` on desktop, a download through `\27SAVEPNG` on the web). Part of the match screen, so the host keeps simulating. |

| `gfx/bloom.lua`, `gfx/hud.lua` | Bloom pass; HUD/card drawing (face-down backs, wrench mark, barrier, score chips). |

| `online/snapshot.lua` | Host→client snapshots (~30 Hz, lz4 when large): players (incl. prediction state, ping, stats), bullets, wells, round history, objects, effects, barrier, fx/sound events, the current pick. |
| `online/active.lua` | Which session the lobby/match/settings screens use: Steam `session` or `lan`. ### Online model
- The host runs `World`, applies remote inputs (INPUT packets with sequence numbers), and broadcasts snapshots. Bots run on the host.
- Clients build proxy tables with the `Player`/`Bullet` metatables and reuse the same `draw()` code. Map objects are rebuilt from the map list and updated from snapshots (`Match.objViews`).
- **Client prediction:** the client simulates its own player (`Match:predictStep`, a real `Player` in a stub world), and on each snapshot resets to the host state for the acked input and replays newer inputs (`Match:reconcile`). Other players render `INTERP_DELAY` behind between snapshots. Anything that changes movement needs to be in the snapshot's prediction fields.
- Before START the host sends MAPS, CARDS (session lists; custom/edited ones as text) and RULES; clients ignore snapshots until MAPS arrived.
- Late joiners get the same setup (`Match:sendSetup`) and spectate (`mySlot == 0`). Dropped players keep their slot for 60 s (`playerKey`: Steam ID or the LAN client token).
- **If you add a field that `Player:draw`/`Bullet:draw` reads, add it to `online/snapshot.lua` and `Match:applySnapshot` (`screens/match.lua`)**, or clients won't see it.
- Card picks are sequential. The current pick (slot, serial, hover, options, queue) travels in every snapshot so everyone watches it. The picker's hover rides in INPUT (`pickHover`) and the choice is CHOOSE(index, serial); a stale serial is ignored.
- Match-over votes: clients send VOTE (continue / new match); the host's `world.votes` travels in the snapshot (one byte per player) and the host's buttons show the tally. Votes are only a suggestion; the host's buttons decide.
- Gameplay rules (cards offered, picks per round, rarity weights, per-card rarity/disabled, timer and barrier options, mode, votes, bans) come from the **host's** settings: the host sends RULES after START and again on New Match, and clients call `Cards.applyRules`. Local play and the host build them with `Settings.cardRules()`.
- In the lobby a client sends LOBBYHELLO (its hat and face); the host replies with MAPS, CARDS and RULES, and resends them when it closes Settings. `session.hostRules` drives the client's read-only Settings > Gameplay view. The main menu restores the local lists.
- Map votes (MAPVOTE: option, +128 to confirm) and card bans (CARDBAN) go client to host; their state travels in snapshots. Card and map selection are keyboard/gamepad only (phones tap). Local players vote and ban in turn.

## Rules and gotchas
- **Cards and maps are data files.** Change built-in ones by editing `data/cards|maps/*.txt` (or build them through the editors) and keep `order.txt` in step. Stat lines on cards are generated from `row`s (`Stats.describe`); notes describe abilities. New stats go in `Stats.LIST` (base value, group, display format).
- Network ids that must only ever be appended to: `sfx.NAMES` (sounds), `Objects.CODES`, fx event kinds (`gfx/fx.lua`), message kinds (`online/net.lua`).
- The designer dislikes easy healing: keep heals small and earned (see memory).
- **Bump `session.PROTOCOL`** whenever the wire format changes (currently `"7"`). Card and map lists are sent by the host, so reordering them no longer needs a bump. Peers with different versions refuse to join.
- **Every card must stack.** Card abilities in `BASE` (player.lua) are **counts of copies, never booleans** (0 = not owned; remember `0` is truthy in Lua, so test `> 0`). When extra copies don't simply add to a stat, give the card a `stack` line describing what they do; `hud.drawCard` shows it. Bullets keep boolean flags (`ghost`, `laser`, `mine`) for drawing and snapshots, with the copy count alongside (`ghostLevel`, `sticky`, `blackhole`, `splitsLeft`).
- New gameplay effects must work with up to 4 players. Use `world:enemiesOf(p)` and `world:nearestEnemy(p, x, y)`, never assume a single opponent.
- Rarity weights are whole percentages that always total 100; change them through `Settings.setWeight`.
- **There are no synergies.** Cards combine through what they do: a bullet's poison and frost carry into its explosions, shards and Hydra heads, and explosive bullets explode on each bounce and pierce (`Bullet:smallBlast`). Add new combinations the same way, never as stat bonuses for owning a set of cards.
- **A team is a colour.** With `rules.teams`, `p.team` is the player's palette index, up to `rules.teamSize` players can share one, and `World.teamName` names it. Without teams `p.team` is nil and colours are unique. `rules.friendlyFire` works in every mode and also means you can hurt yourself: go through `World:canHurt`.
- Every map needs 4 spawns (`spawns[1..4]`) that land on solid ground, away from hazards. The map editor's `Editor:validate()` checks this; built-in maps should pass it, and bots should finish rounds on them (bot-vs-bot harness).
- `Player:hit(amount, dx, dy, knock, source)`: always pass the attacker as `source` (Thorns and Frostback need it). Damage goes through armor, then the Shield Generator shield, then Decay/HP.
- Bullets spawned by other bullets (Shrapnel shards, Hydra heads) use `Bullet:spawnChild`, which marks them `isChild` and zeroes chain effects so they can't multiply. Cluster mini-blasts are `isCluster` clones. Keep new chain effects behind these flags.
- `Player:draw` also reads `shield` and `stats.sentry`; both travel in the snapshot.
- `fx.*` calls on the host are recorded into `fx.recorder` and replayed on clients. Keep fx calls deterministic in shape (`burst`, `ring`, `addShake`, `clear`).
- Steam binaries (in `lib/`) must match an SDK version. Currently `luasteam.dll` / `luasteam.so` are **v6.0.0** (luasteam GitHub release, built for SDK 1.65). `steam_api64.dll` / `libsteam_api.so` are SDK **1.65**, taken from Steamworks.NET `com.rlabrecque.steamworks.net/Plugins/`. A mismatch shows up as "The specified procedure could not be found" (Windows) or an undefined-symbol error (Linux). Windows and Linux players can play together.
- `love.window.setMode` fails while a canvas is active, and screens draw (and handle widget clicks) on `app.canvas`. Always change the window through `Settings.applyWindow()`: it defers to `Settings.update()` (called from `love.update`) when a canvas is active. In the settings screen, window mode, monitor, resolution and VSync are pending until **Apply**.
- Settings are saved to `settings.txt` in the LÖVE save folder (flat `key=value`, plus `bind.<scheme>.<action>=key` and `card.<id>=<rarity>,<on|off>` lines). `Settings.resetBinds` mutates in place because input states hold references to the bind tables.

## Testing approach (headless, no Steam needed)
- Harnesses load files through `love.filesystem`, which only sees the harness folder: **symlink the repo's `data/` into the harness folder** or the game falls back to a single map and no cards. Symlink `assets/` too (fonts). Don't create a folder named after a game module (`game/`, `core/`...) in a harness. Set `require("core.app").noSlide = true` so screenshots aren't mid-transition, `require("gfx.sfx").silent = true` for speed, and `Settings.values.startCards = 0` unless testing the start picks.
- Bots make good stress tests: bot-vs-bot rounds on every map should end (no stalls) without errors.
Put test harnesses in the session scratchpad, not the repo. Pattern:
```lua
package.path = "<repo>/?.lua;" .. package.path   -- lets require "game.world" find <repo>/game/world.lua
dofile("<repo>/main.lua")          -- defines love.load/update/draw/run; override love.run to drive the test yourself
love.keyboard.isDown = function(...) ... end   -- fake input
```
- **Local/UI:** drive `love.keypressed`, read state with `require("core.app").base()`, and screenshot with `app.canvas:newImageData():encode("png", name)` after `love.draw()`.
- **Network:** `hub = net.loopback(0.1)`, then `Match.newClient(slots, i, winScore, hub:endpoint(id), "H", nil, {popEvents=fn})` and `Match.newHost(slots, winScore, hub:endpoint("H"), {popEvents=fn})`. Construct clients **before** the host, because `newClient` resets `fx.recorder`. Set `fx.recorder = nil` while updating clients, and compare client proxies with `host.world.players`.
- Give the harness its own `conf.lua` with a separate `t.identity` (and one per process if running several in parallel, since they share `settings.txt`). Run with `love <harnessDir>` under `timeout`, then view the screenshots.
- On the web a canvas can read back as `rgba4`, and `ImageData:encode("png")` hangs on that: copy to `rgba8` first (see `Recap.update`).
- **Browser build:** serve `dist/web` with `python3 -m http.server`, then drive it with `puppeteer-core@22` (install it in the scratchpad) using the system Firefox: `{ product: "firefox", browser: "firefox", protocol: "webDriverBiDi", executablePath: "/usr/bin/firefox", headless: true, args: ["--no-remote"], extraPrefsFirefox: { "dom.w3c_touch_events.enabled": 1 } }`, with `TMPDIR` set to a scratchpad folder (the user's own Firefox may be running). For phones, use a 844×390 viewport and dispatch `TouchEvent`s on the canvas. Map game coordinates to page clicks through the canvas's `getBoundingClientRect()`. In Firefox's protocol the space key is `" "`, not `"Space"`. Check the console for Lua errors.
- **LAN (real sockets):** run two LÖVE processes with separate identities: a host harness that calls `lan.host(...)` and `app.base():start()` once `#lan.members >= 2`, and a client harness that opens `screens.lan`, joins the first of `s.games` and fakes keys. Compare the host's `world.players[2]` with the client's `proxies`. For browser clients, set `lan.webDirCache` to a love.js build and drive `http://127.0.0.1:27960/` with puppeteer (Chrome works too).
- **Real Steam (Linux, Steam running):** override `love.filesystem.getSource` to return the repo path, then `require("online.steam").init()`.
